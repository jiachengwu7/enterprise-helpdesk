# 前端实现说明

独立 React 18 + TypeScript + Vite 5 应用。所有业务请求均通过 Java 的 `/api`，没有浏览器到 Python 的直连，也没有引用原项目的代码或依赖目录。

## 运行与验证

在本目录执行：

```sh
npm ci
npm run dev
npm test
npm run build
```

开发服务固定监听 `http://127.0.0.1:5180`，`strictPort` 开启；`/api` 代理到 `http://127.0.0.1:8180`。根目录启动器负责基础设施和两个后端服务。

2026-10-26 验证结果：`npm test` 的 4 个测试文件、13 项测试全部通过；`npm run build` 的 TypeScript 检查和 Vite 生产构建通过，无构建警告。输出位于 `dist/`。真实浏览器及真实后端的集成检查由根项目脚本独立执行，不能以组件测试代替。

已安装 `@playwright/test`，供根项目浏览器验收使用。初次依赖安装遇到 sandbox DNS 不通，获授权的联网安装成功；Prettier 使用 npm 镜像完成安装。仓库锁文件保留依赖版本，源码已用 Prettier 格式化。

## 功能与源码

- `App.tsx`：登录、会话恢复、退出、角色导航、真实仪表盘、近期工单与快捷入口。
- `Assistant.tsx`：会话创建/读取/删除，问答、来源片段和授权下载，模型/仅检索/离线状态，工单草稿确认或拒绝，创建成功后跳转工单。
- `Documents.tsx`：文档搜索、索引状态筛选、multipart 上传与替换、删除、下载；存在排队或处理中项目时每 4 秒刷新索引状态。
- `Tickets.tsx`：搜索、状态/优先级筛选、幂等键创建、详情、部门内分配、合法状态流转、解决方案、评论、关闭评分。
- `Management.tsx`：管理员创建用户与用户列表、白名单健康字段、无密钥的本机配置说明。
- `api.ts`：sessionStorage token、Bearer 头、JSON envelope、实际 HTTP 错误、会话过期事件、二进制下载。上传不覆盖浏览器的 multipart Content-Type。
- `permissions.ts`：页面操作边界。服务端仍是最终授权者。
- `ui.tsx`：取消过期加载结果的 hook、错误/空/加载状态、标签、具备焦点约束和 Escape 关闭的弹窗。
- `style.css`：本地图标与纯 CSS 图形，桌面及移动布局，无远程图片或字体请求。

## 测试范围

API 测试验证 envelope 解包、真实 HTTP 失败不能被成功 code 覆盖、离线代理错误、401 清理会话和 multipart 边界。权限测试验证员工禁止维护文档、处理员跨部门限制、创建人关闭条件和状态机。组件测试验证失败登录、员工导航、首次发送响应中断后的待确认恢复，以及 AI 离线不能误报仅检索。

测试中的 fetch 替身仅用于外部 HTTP 边界。生产没有静态指标、伪答案或样例工单。

## 关键交互和边界

账户表单标签为“用户名”“密码”“登录工作台”；导航按钮分别为“工作概览”“知识助手”“企业知识库”“工单协作”“系统状态”“用户管理”。问答输入标签为“输入问题”，发送按钮为“发送问题”，上传文件标签为“选择文档文件”，可用于稳定的无障碍访问与浏览器测试。

只有最新一次发送结果的 `Answer.mode` / trace 由契约明确返回；历史 `Message` 不含 mode，因此历史回放不会推测每条回答的模型执行方式。页头显示当前服务配置情况，刚产生的回答显示真实 mode。后端内容本身仍应保留检索模式标记。

前端不接收或显示 API Key。模型实际调用是否成功，需要配置本机 `ai-service/.env` 后独立验证；“已配置”不等于“已验证”。业务服务无法连接时显示错误，不展示伪造的成功数据。
