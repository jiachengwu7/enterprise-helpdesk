# Shared contract v1 — exact integration surface

IDs are UUID strings except department IDs `IT`/`HR`. Dates ISO8601. Role ADMIN/AGENT/EMPLOYEE, visibility PUBLIC/DEPARTMENT, priority LOW/MEDIUM/HIGH, ticket status OPEN/IN_PROGRESS/RESOLVED/CLOSED. Every browser endpoint below is prefixed `/api`; Java JSON envelope `{code:200,message:"success",data:...}`, errors matching HTTP status, message safe. Bearer opaque login token. Frontend saves token in sessionStorage. Multipart uses FormData. No browser calls Python.

## Browser API (Java 8180)
- GET /health unauth -> {status:"ok"} inside envelope.
- POST /auth/login {username,password} -> {token,user}; User={id,username,displayName,departmentId,role}.
- GET /auth/me -> User; POST /auth/logout -> null.
- GET /departments -> [{id,name}]. GET /users -> User[] (staff list for assignment; employees forbidden); POST /users ADMIN {username,password,displayName,departmentId,role} -> User.
- GET /dashboard -> {documents,tickets,openTickets,resolvedTickets,conversations} numbers scoped to caller.
- GET /system/status -> {ai:object, database:"ok", version:"1.0.0"}; AI object from Python health, or {status:"unavailable"}. All authenticated roles can view nonsecret health.
- GET /documents -> Document[]; Document={id,title,filename,departmentId,visibility,version,status,chunkCount,error,createdAt,indexMode?}. status QUEUED/PROCESSING/READY/FAILED. POST /documents multipart {file,title,departmentId,visibility} -> Document; PUT /documents/{id} same multipart -> Document version+1; DELETE /documents/{id} -> null; GET /documents/{id}/download binary. Only ADMIN or AGENT manage; AGENT own department, ADMIN any. Employee read access PUBLIC or own dept. Max 10MB; txt/md/pdf/docx only. No raw paths or raw parser/provider errors in responses.
- GET /conversations -> [{id,title,createdAt,updatedAt}]; POST /conversations {title?} -> same item; GET /conversations/{id} -> {id,title,messages:Message[],pendingProposal:Proposal|null}; DELETE /conversations/{id} -> null. Only owner (even ADMIN cannot read another user's chat).
- POST /conversations/{id}/messages {question,requestTicket?:boolean} -> Answer; nonblank max4000, requestTicket defaultfalse. Message={id,role:"user"|"assistant",content,sources:Source[],proposal:Proposal|null,createdAt}. Persist user and assistant turns. Reject sending new question while pending confirmation (409).
- Answer={answer,sources:Source[],proposal:Proposal|null,mode:"llm"|"retrieval-only",trace:string[]}; Source={documentId,title,filename,chunkIndex,content,score,version}. Proposal={id,title,description,priority}.
- POST /conversations/{id}/confirm {proposalId,approved:boolean} -> {answer,ticket:Ticket|null}. Java verifies ownership/pending proposal, creates idempotently in transaction if approved, resumes Python (retry-safe). Repeating same approval returns same ticket. Invalid/mismatched proposal ->409. Rejection also persisted and resumes graph.
- GET /tickets -> Ticket[]; POST /tickets {title,description,priority,idempotencyKey} -> Ticket (employee creation own department); GET /tickets/{id} -> TicketDetail.
- PATCH /tickets/{id} {status?,assigneeId?,resolution?,rating?} -> Ticket. ADMIN/AGENT assign within ticket department and transition OPEN->IN_PROGRESS->RESOLVED; resolution required at RESOLVED. Creator (or ADMIN) closes RESOLVED->CLOSED with rating1..5. Other transitions409. Ticket={id,number,title,description,priority,status,departmentId,creatorId,creatorName,assigneeId,assigneeName,resolution,rating,createdAt,updatedAt}; TicketDetail extends Ticket with comments:[{id,authorName,content,createdAt}]. POST /tickets/{id}/comments {content} -> comment. Never expose another employee's ticket.

## Internal API (Python 8101)
Every /internal endpoint requires constant-time checked header `X-Service-Token`. Shared secret from root .env `SERVICE_TOKEN` forwarded as AI_SERVICE_TOKEN. Do not accept identity/scopes from public requests. GET /health unauth, minimal nonsecret readiness: {status,modelConfigured,embeddingConfigured,indexMode,database,redis,storage,version}. Python normal JSON not Java envelope.

- POST /internal/documents {id,title,filename,departmentId,visibility,version,contentBase64} -> {status:"QUEUED"}; store original to S3 and metadata/job durably; worker uses version check and atomic chunk replacement. Document registry belongs Python for index metadata; Java owns authoritative access metadata.
- POST /internal/documents/status {ids:string[]} -> {documents:[{id,status,chunkCount,error,indexMode}]}; missing IDs report FAILED with safe message.
- DELETE /internal/documents/{id} -> {deleted:true}; tombstone/cancel queued work; physical chunks removed and S3 cleaned.
- GET /internal/documents/{id}/download -> binary original active version.
- POST /internal/chat {conversationId,userId,departmentId,role,allowedDocumentIds:string[],question,requestTicket:boolean} -> Answer. Java computes whitelist from current authorized active documents. Python MUST intersect whitelist with actual indexed active docs. Never reuse previous sources when rights/documents change. Scope is current request and not model-generated. Only current authorized evidence goes to model; historical assistant text excluded from retrieval authority. Graph persisted thread key `userId:conversationId`.
- POST /internal/chat/confirm {conversationId,userId,proposalId,approved,ticketId:string|null,ticketNumber:string|null} -> {answer}; resume current pending graph with decision/Java outcome. No Python ticket-table writes. Safe idempotent replay.
- POST /internal/chat/state {conversationId,userId} -> {question:string|null,pending:Answer|null}; authenticated read of user-qualified pending interrupt. Returns null when none or finished. Java reconciles missing pendingJson after lost Python response under conversation lock, validates/masks current evidence before saving history; no model call or business write by this Python endpoint.
- DELETE /internal/conversations/{conversationId}?userId=... -> {deleted:true}; delete user-qualified checkpoint.
