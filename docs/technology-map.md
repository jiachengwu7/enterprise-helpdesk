# 技术在项目里做什么

这是一套 Java + Python + React 的本机应用，学习时沿一次用户操作读代码。

| 技术 | 具体责任 | 为什么使用 |
| --- | --- | --- |
| React / TypeScript / Vite | 登录、知识助手、文档、工单和系统状态页面 | 组件与类型组织交互；开发代理把浏览器 API 发往 Java |
| Spring Boot / Spring Security | HTTP 入口、登录令牌、角色与部门授权 | 身份和业务权限统一控制，模型不能给自己授权 |
| JPA / Flyway / PostgreSQL | 用户、令牌、文档归属、会话和工单，数据库迁移 | 重启保留数据；事务与唯一约束保证确认重试不重复建单 |
| FastAPI / Pydantic | 内部 AI HTTP 接口和参数校验 | 与业务服务明确分工，拒绝不合法请求 |
| LangChain | 提示消息、模型客户端、Embedding、文本分块、结构化工具 | 把模型相关组件接到真实业务流程 |
| LangGraph | 检索、回答、工单草稿、暂停确认与恢复 | 明确每一步的状态和路由，待确认流程可恢复 |
| PostgreSQL checkpoint | 保存图的执行进度 | 页面关闭或服务重启后仍能继续确认 |
| pgvector + 关键词检索 | 语义与词面召回；结果带文档版本和原文 | 回答有出处；权限先于内容进入模型 |
| Redis Streams | 文档入库任务、消费与重试 | 上传请求无需等解析、Embedding全部完成 |
| RustFS / S3 | 保存上传原件与授权下载 | 大文件与结构化业务数据分别存储 |
| Docker Compose | 启动独立 PostgreSQL、Redis、对象存储 | 固定环境，数据卷持久化，与原项目隔离 |

## 上传一次文件

浏览器 -> Java 验证员工角色及目标部门 -> Java 保存文档归属 -> Python 保存原件、发送入库任务 -> worker 解析、分块、向量化 -> 原子发布当前版本。失败在文档列表显示，不能以“上传成功”代替“已可检索”。

## 提问一次

浏览器 -> Java 查登录用户与会话归属 -> 计算可访问文档 ID -> Python 图检索 -> LangChain 模型根据证据回答 -> Java 保存消息 -> 页面展示回答及来源。

没有模型配置时只显示检索证据及明确状态，不把原文拼接冒充模型生成。

## 确认一张工单

图准备草稿 -> interrupt 保存待确认状态 -> 用户点击确认 -> Java 检查草稿归属、在事务中幂等建单 -> 图收到结果后 resume -> 处理员接单、处理、填写解决方案 -> 员工确认关闭并评价。

重点比较：checkpoint 负责“流程走到哪里”；数据库事务和唯一键负责“业务只执行一次”。两者不能互相替代。
